# 账号与登录会话框架

此目录是账号业务的接口和生命周期框架，目前不能完成真实注册、密码登录或会话续期。
默认关闭；启用时，尚未实现的密码/存储适配器会阻止服务启动，不会签发占位凭据或放行请求。

## 职责与调用

```text
server/api：接收业务请求，投递到有界账号工作池
    → AccountService：同步账号业务边界
        → PasswordHasher：密码哈希与验证
        → AccountStore：用户和登录会话持久化
    → 将结果投递回连接所属 I/O 调度线程
```

`AccountService` 不依赖 HTTP、Room、WebRTC 或媒体线程。`ServerApp` 装配依赖；
业务方法由账号工作线程调用，不能在媒体收包回调中执行密码计算或数据库操作。

`Start()` 校验配置、密码适配器就绪状态并打开存储；失败时不进入运行状态。
`Stop()` 幂等地关闭已打开的存储。业务方法持共享生命周期锁，可以并行执行；
启动和停止持独占锁，停止会等待在途方法返回。存储接口负责自身的并发访问同步。
停止前仍需排空 API 工作池，防止排队任务稍后访问已销毁的服务。
真实密码计算应在数据库事务外执行。依赖对象由服务持有，外部不得关闭运行中的存储。
存储启动抛出异常或返回错误时，服务关闭部分初始化资源并返回失败。

## 已建立的数据与接口

- `User`：可以返回给接口层的用户资料；`StoredUser` 另外包含密码哈希。
- `LoginSession`：持久化登录会话，仅存随机登录凭据的摘要。
- `AccountIdentity`：登录会话验证后的可信身份，不包含房间发布/订阅权限。
- `AccountResult<T>` / `AccountStatus`：显式失败，默认构造不会成功。
- `AccountService`：创建账号、登录、解析登录会话、续期和退出。
- `AccountStore`：账号唯一性、用户/会话一致性读取、会话创建和轮换的事务边界。

登录会话与 `service/Auth` 的入房 JWT 分别管理。后续会议业务先验证登录会话，
再检查会议成员资格和角色，最后签发指定会议的 JWT。当前框架没有实现此签发流程。

## 待实现顺序

1. 实现 SQLite 表结构迁移、规范化账号唯一约束，以及存储接口的原子事务。
2. 用成熟库实现 scrypt，包括随机盐、存储参数格式、参数上限和常量时间比较。
3. 明确注册/邀请策略，再实现创建账号。实现登录和随机会话凭据生成，
   创建会话前在事务里复核账号状态及凭据版本，避免禁用或改密竞态。
4. 实现会话到期、撤销、凭据版本检查；续期需要原子轮换，旧凭据立即失效。
5. 完成 HTTP 协议接入、HTTPS 部署、输入限制、登录频控和凭据传输规则。
   若采用浏览器 Cookie，需要 Secure/HttpOnly、明确 SameSite 策略及 CSRF 防护。
6. 补充账号禁用、修改密码与会话撤销业务，再连接会议成员权限及在线会话撤权。

`SqliteAccountStore` 目前不打开或创建数据库，所有方法返回 `NotImplemented`。
`ScryptPasswordHasher` 目前不执行哈希计算，也不会验证通过任何密码。
`AccountService` 即使注入可启动的测试依赖，业务方法仍返回 `NotImplemented`。
当前测试验证启动失败、依赖缺失、幂等停止、存储失败清理和占位实现不会放行登录。

本构建目标目前依赖 C++17 和线程库。实现适配器时，应在 `packetia_account` 目标中显式增加
SQLite/OpenSSL 等实际依赖，避免通过媒体目标间接获取链接库。
