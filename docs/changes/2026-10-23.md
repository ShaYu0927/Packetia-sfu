# 2026-10-23 服务端切网路径状态与媒体控制恢复

本轮将路径恢复通知接入核心 C++ 链路，解决 ICE restart 或地址重绑定后，媒体发送控制继续沿用旧路径状态的问题。

```text
WebRtcService → WebRtcSession → WebRtcMediaTransport → SendSideController
```

## 路径生命周期

- 新增 `WebRtcNetworkPath`，描述 New、Checking、Ready、Failed、Closed，以及 ICE 代次、路径修订号和可用地址。
- `WebRtcSession` 在启动、restart 提交、新路径可用、失败和关闭时通知上层，提供 owner 线程内的状态查询。
- Ready 要求选中地址且 DTLS/SRTP 可用；restart 提交不提前报告恢复成功，失败的协商准备保留原路径状态。
- 同代次地址重绑定和同地址的新一轮 restart 都可产生路径更新；重复检查及重复提名不会重复报告 Ready。
- `WebRtcTransport` 增加线程安全的选中地址快照读取。

## 媒体适配与发送控制

- `WebRtcService` 通过弱引用将路径通知接到 `WebRtcMediaTransport`。
- Checking、Failed、Closed 禁用发送控制；Ready 重置旧路径的发送历史、反馈适配状态、TWCC 新鲜度和 GCC 估计，等待新路径反馈。
- 保留 TWCC 序号分配器及 sender SSRC/时钟登记，不重建房间、轨道、订阅和已建立的加密会话。
- 异步发送携带路径 epoch；切网前已排队、尚未执行的任务在 owner 线程检查代次后丢弃，避免积压包直接进入新路径。
- 移除 Send/收包时自行启用控制器的行为，由明确的路径生命周期通知控制可用性。

## 构建与文档

- 为可选 `log/Test` 和 `server/examples/WebRtcRoomDemo.cpp` 增加存在性检查，当前检出缺少这些文件时仍能生成核心程序与回归目标。
- README 增加核心路径恢复能力、当前边界和阅读入口。
- 新增[服务端切网恢复框架](../network-handover-framework.md)，说明线程契约、调用链、扩展位置及后续任务。

## 验证

2026-10-23 在本机现有 `build/webrtc-integration` 配置验证：主程序与以下测试目标构建成功，六个相关 CTest 入口通过。

```sh
cmake --build build/webrtc-integration \
  --target Packetia test_webrtc_session test_rtp_input test_weak_network_manual \
  test_webrtc_service test_webrtc_crypto test_datagram_transport -j4
ctest --test-dir build/webrtc-integration --output-on-failure \
  -R '^(test_webrtc_session|test_rtp_input|test_weak_network_manual|webrtc_service|test_webrtc_crypto|test_datagram_transport)$'
git diff --check
```

| 测试入口 | 相关覆盖 |
| --- | --- |
| `test_webrtc_session` | restart 通知时机、旧凭据拒绝、重复提名去重、同代次重绑定、同地址的新代次恢复、旧地址过滤、失败与关闭 |
| `test_rtp_input` | 媒体适配器与实际 session 回调衔接，等待期间禁用控制，旧排队发送作废，新路径恢复发送；现有 endpoint/RTP 回归 |
| `test_weak_network_manual` | 清除旧发送历史，保留 TWCC 序号与 sender 登记，RR 回退及新 TWCC 生效 |
| `webrtc_service` | 房间、鉴权、恢复、路由与业务服务回归 |
| `test_webrtc_crypto` | 真实 DTLS/SRTP 回归 |
| `test_datagram_transport` | 传输与 UDP mux 回归 |

新增路径迁移断言使用真实 STUN 消息构造与认证处理，媒体加密边界使用测试替身；单独的真实 DTLS/SRTP 回归不等于完整的真实加密切网验收。构建仍有既有重复库链接等警告，本轮未运行全量 CTest 或新增弱网压测。

## 当前边界与后续工作

- 客户端仍负责 ICE restart offer、候选收集和主动检查；尚未完成手机 4G/5G 或 Wi-Fi/移动网络切换验收。
- 恢复后的关键帧请求、路径恢复耗时统计、客户端有界重试和信令黑洞检测仍需补齐。
- 异步 Send 成功仍表示入队成功，发送历史尚未改为按真实 socket 完成回执记录；旧路径早期 RR 统计也无法仅凭本地路径代次精确隔离。
- 路径状态回调须在会话 owner 线程执行，不得抛异常或同步重入会话控制操作；自定义媒体适配调用方需要显式连接该回调。
